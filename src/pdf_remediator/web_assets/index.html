    Remove the font character lists?
    

    Many PDF programs write an optional list, called a CIDSet, inside each embedded font. It names the characters the font contains. When that list is wrong or incomplete, the strict PDF/UA-1 check fails even though the page looks right and reads right.
    

    If you allow this, the program deletes the list from every embedded font that has one. It does not change any page picture, any text, or the drawing of any character. PDF readers and screen readers work from the font itself, not from this list. Your original PDF is never changed, and the removal is recorded in the report.
    

    Choose “Keep the lists” if you need the fonts left exactly as the program that made the PDF wrote them.
    

    

    Rebuild the missing letter dictionary?
    

    Some PDFs draw their text with fonts that carry no letter dictionary (a ToUnicode map). The page looks right, but a screen reader, search or copy and paste receives control characters instead of letters.
    

    If you allow this, the program reads each page the way a scanner would (OCR), lines up every drawn character with the word read at that spot, and writes the dictionary only where the readings agree and a check on held-back words comes out at least 95 % right. No page picture or page box changes, and your original PDF is never changed.
    

    The result is an inference from the reading, not a fact. A required review item asks a person to compare the extracted text with the pages, and fonts that stay partly unmapped are named there. This works on its own, so reading scanned text and character-mapping corrections are switched off while it is on.
