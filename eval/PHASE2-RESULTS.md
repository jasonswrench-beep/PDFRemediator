## Exact preservation and the separate character policy

The painting processor is `source-aligned-painting-1.1`; its API remains `preserve_painting(source, engine_output, destination, *, allow_tag_regrouping=False)`. Defaults remain conservative. The added repair addresses 14 table-of-contents titles where the engine split one original text-show across a Link and LBody while the LBody also retained a separately painted page number.

Only a structurally proved, single-target list-link pattern is regrouped. The complete title uses its exact original source operator; trailing body MCIDs retain their order and owners; the existing Link keeps its annotation and target. Unsupported nested/non-prefix structures, unresolved tails, conflicting destinations, extra link semantics, or meaningful label payloads are refused. Each semantic reassignment produces its own pending review occurrence. No generic text-position interpreter, guessed glyph, or broader render tolerance was introduced. [Repair details and adversarial regressions](phase2-preservation/README.md).

The independent preservation experiment records exact original-to-preserved rendering for **both** complete books, with unchanged source/raw engine hashes and implementation files. Synthetic page 2 and real-book pages 14 and 119 also received developer visual spot checks, tied to exact PDF hashes. Those spot checks supplement the every-page comparisons; they are not assistive-technology acceptance tests. [Experiment summary](phase2-preservation/run-1/summary.json), [visual QA](phase2-preservation/run-1/visual-qa.json).

All release comparisons use pinned PDFium at **96 dpi, RGB on white, annotations enabled**, with zero permitted changed pixels (`pixel_delta=0`, `max_changed_fraction=0`). Page geometry, annotations, bookmarks, destinations, and page labels are checked independently. The synthetic candidate's ordered and multiset text comparisons both pass with zero added/removed tokens.

The published book explicitly enables regrouping and the existing bounded source-mapping option. Two absent TeX mappings are sourced from unchanged embedded Type1 programs and the pinned CTAN `pdfx` authority: `mapsto` to U+21A6 and `radicalBig` to U+221A U+FE02. They affect exactly **nine recorded glyph occurrences** on pages 74, 193, and 194; every other extracted character is verified unchanged. Existing mappings are never rewritten and no font is substituted.

Under `authoritative-character-mapping`, the unchanged original and independently corrected reference remain visually identical on all 244 pages and retain navigation. The final candidate matches that reference exactly under the declared full-page comparisons. Its reference text **multiset passes with zero added/removed tokens; ordered text remains `needs-review`**. The raw original-to-final and original-to-reference text comparisons remain recorded failures because those nine fallback characters intentionally change. This is a named, independently proved character-correction policy; it is not unchanged original text or a relaxed pixel tolerance. Mathematical meaning, compound symbols, variation-selector behavior, and semantic reading order remain human work.

The final published-book baseline has 12 failing rules and 44,352 failed checks; the final strict validator has none. Complete rule inventories support the recorded fixed/remaining/newly-failing rule comparison. Partial assertion details do not justify an assertion-by-assertion repair history. ## Local review, grouping, and revalidation

The local browser application supports file selection, controlled processing options, batch progress/cancellation, original/result page previews and nearby text, blocker explanations, title/figure editing, explicit acceptance, grouped occurrence review, draft suggestions, separate result download, and bound review export. The private service binds to `127.0.0.1`; its random launch token remains in the URL fragment. Host, token, Origin, content type, request size, route boundaries, and output bindings are exercised by the HTTP tests. No arbitrary filesystem route is served.

Draft editing, accepting a value, applying accepted edits, and completing artifact review remain separate actions. Applying accepted changes creates a new bundle and reruns original-baseline validation, final validation, supplemental checks, and preservation against the exact assessed output hash. Explicit checkpoint adoption can retain preparation across an application update; old automated passes never become new passes. Altered manifests, context inventories, checkpoints, references, cache provenance, queued sources, or queued exported decisions are refused. Source/prepared/output changes invalidate approval reuse; conflicting revisions cannot overwrite newer work.

The [final book grouping evidence](../output/phase2/core-final-private/grouping.json) records **630 pending manual items, 623 regrouping occurrences, 10 regrouping patterns, and 19 total workspace groups**, with unique occurrence addresses and zero approvals. The browser displays **17 manual groups**; the other 2 workspace groups contain decisions. Grouping reduces navigation, not the number of unresolved judgments. Explicitly selected members retain their own identity, page/context, membership digest, reviewer/date, and artifact binding. Group approval does not infer that all similar occurrences have the same meaning. Earlier [workspace grouping evidence](../output/phase2/workspace-evidence/summary.json) describes an earlier checkpoint and its different counts; the final counts above supersede it for this release.
